# 学习整理：大材料生成与来源绑定

本次修复的目标是让已保存的大材料由应用自动安排处理，而不是把单次请求的大小限制当成整门课程的准入门槛。保留现有学习页、材料范围、账号隔离和历史成果；未更换学习模型或其他产品配置。

## 用户流程

上传并确认整理后，应用先准备选定材料，再分部分阅读与整理。处理中显示已完成部分数，旧成果仍可阅读；本批章节完成后统一发布。Quiz 仍可直接从材料生成，不依赖框架。题组在后台生成，完成后选择练习或测验；答题、揭示答案和续做仍由代码完成。

明确失败且来源未变时可以继续未完成部分。网络结果未知的请求不自动重发；刷新、重登或重复提交也不产生重复调用。继续操作仍有一次失败部分的重试上限，不能无限消耗 Provider。

## 实现边界

- `generation-sources.ts`：按段落、必要时按句子边界拆分；片段保留原段号及字符位置，全部正文参与处理。`r1` 等别名只在当前请求中有意义，闭包精确还原原材料和段落。不存在的别名继续拒绝，不猜来源、不放宽校验。
- `framework-service.ts`：逐部分生成并检查来源，暂存结果，最后原子发布章节。多部分整理说明如实说明整理范围，不能当作新的全课程语义分析。
- `quiz-planning.ts`：长输入先逐部分阅读建立定位索引，再安排考点；最终出题重新提供被选中的实际原文，索引不是答题依据。有限题量只是对范围内考点的取样，不能宣称考查全部内容。跨材料可在同题依据包中联合使用。
- `overview-planning.ts`：大总览按真实跨批次章节组合读取对应原文，保留章节别名、来源和原有局部拒绝规则。处理规模随章节关系组合增加，不把目录拼接视为关系验证。
- `generation-parts.ts`：学习专属检查点；SQLite 版本 10 新增一张表，原有表、题目顺序、答案和作答不迁移重写。存储请求指纹、处理状态、有效结果及脱敏用量，不另存课程原文。父任务、账号、材料版本和删除检查继续控制发布。
- 删除材料清除该材料涉及的暂存结果；保留已有学习成果及来源已删除状态。删除学习页移除全部所属检查点，晚到返回不能重建数据。
- 定位索引、考点选择和出题统一使用既有 JSON 传输的 `items` 根字段，避免提示词与传输格式冲突。索引仍不作为出题事实来源。
- 长原文来源抽屉按真实段落高度定位；不再用估算的折叠高度滚动到后段，避免第 70 段链接打开后落在其他段落。

`LEARNING_AI_MAX_INPUT_CHARS` 目前保留兼容名称，但只用于安排单次请求，不能据此拒绝整份选定材料；请求还会计入提示词与格式开销。较长任务会产生多次调用且等待更久，输出仍受当前服务的实际单次输出能力约束。这不是“模型拥有无限上下文”的承诺。大小、安全、截断与来源错误仍必须明确处理。

真实模型对跨片段条件、关系、题目唯一性和解释的质量仍需另行有界验证。结构合法和引用可达不证明语义正确；本轮不能称真实 Provider 或生产验收通过。
