## 用户操作与当前能力

选择已保存的文本/TXT 或已转写录音 → 点击“整理所选材料” → 保存本次范围 → 明确配置的学习调用生成一批章节与总览 → 校验并整批保存 → 展开阅读、回看原段落、编辑标题/解释、移动知识点、记录个人笔记 → 刷新或重新登录后重开。

材料本身不触发模型调用。选中未解析 PDF 会明确阻止本次整理，不会将其当空文本忽略。没有学习配置时返回 `learning_generation_not_configured`，页面显示“学习生成尚未配置”，不使用示例结果、Work/Daily/Date 设置或其他产品历史。测试 mock 仅由测试依赖注入或专用测试进程 preload 提供，正式页面没有 mock 开关。

默认可折叠 AI 章节/知识点，展开后显示解释及段落来源。没有根据文本自动冒充“原材料目录”。AI 正文、明确标记的材料外补充、用户编辑和个人笔记分开；单独添加笔记不会将原 AI 解释标为用户改写。移动知识点会一起移动其来源和笔记，不修改材料原件。

## 保存、追加与来源

- `LearningRepository` 原账号库 schema 3 → 4 只增加 `learning_framework_runs` 和 `learning_framework_chapters`，不重写原材料或 ParsedDocument。迁移在同一个 immediate transaction 中，失败回滚。没有新依赖、共享任务平台、Memory、检索或通用上传路径。
- 一次用户动作产生一个稳定批次 ID，选定材料身份和原始字节 SHA-256 存在批次里；不另存输入原文缓存。同 ID 同范围读取已有结果，同 ID 异范围拒绝。每页同时最多一个生成批次，不因双击或重复 HTTP 提交重复调用。
- 模型结果只允许引用本次材料和确实存在的 1 起点段落；服务端保存原件哈希、段落哈希和原始字符串偏移。来源 API 再检查账号、学习页、章节/节点归属、材料及绑定，返回真实段落位置。结构/可达性校验不是语义验证，没有自动 `verified` 声明。
- 全批章节和 AI 批次概括一起提交，不逐章发布半成品。新批次插入新章节；不会更新旧章节、AI 初始内容、用户解释或笔记。每章保留不可变初始 AI 内容和当前用户版本，章节编辑使用 revision 检查，移动跨两章时同时检查双方版本并在同一事务完成。
- 总览是一份当前章节标题、章节说明和链接的自动汇总，并保留各批次 AI 关系概括。追加、编辑后自动更新目录；它不是再次调用模型生成的跨批次综合文章，不宣称已发现新旧批次之间全部关系。本阶段不创建第二份可编辑的总览正文。
- 请求期间存储 `generating` / `validating` 状态。界面显示 0/1 个响应、已收到响应/整批保存等实际阶段，不编造章节完成数或百分比。刷新可读到批次进度和旧结果；同步请求最长 120 秒，150 秒后未终结批次标为中断。没有后台自动重放；失败后再次生成是用户明确发起的新批次。
- 删除单份材料清除原件及已有解析正文，使未完成引用批次失效；已保存框架、总览和笔记保留，原文引用显示“来源已删除”。旧派生内容不会自动成为新生成依据。删除学习页清除已有材料、框架、批次、笔记等归属内容，保留页墓碑防止迟到写入恢复。尚未开发的对话、题组、作答沿用首版删除规则，本轮不预建其管理。

## 独立学习模型边界

`framework-generator.ts` 复用项目 `parseStructuredJsonResponse` 的流式 Responses 传输。现有 DS Pro 使用 `https://tokenhub.vision-intelligence.tech/v1/responses`，并非 Chat Completions。本次未加另一条协议、未修改 Work 调用方。只共用服务端 `OPENAI_BASE_URL`、`OPENAI_API_KEY` 和既有 `OPENAI_AUTH_HEADER_MODE`；历史 HTTP 配置同项目既有客户端一样固定升级为这个 HTTPS 端点，其他 host/path 拒绝。

学习独立配置：`LEARNING_AI_PROVIDER=tokenhub`、`LEARNING_AI_MODEL=deepseek-v4-pro`、`LEARNING_AI_MAX_INPUT_CHARS`、`LEARNING_AI_MAX_OUTPUT_TOKENS`。没有预算就拒绝，不继承 Work/Daily/Date 的配置；不读取旧阶段的 LEARNING_AI_BASE_URL/LEARNING_AI_API_KEY。`.env.example` 给出 8,000 字符/4,000 tokens 的配置示例，本轮没有启用真实 `.env.local`。

一次整理只有一次流式 Responses 请求，无工具、fallback、自动重试或二次修复，`store:false`、`maxRetries:0`、`reasoning.effort=none`。仅 terminal `response.completed` 的 assistant 正文可进入 JSON/结构/来源校验；HTTP 200、partial delta、截断、缺失 completion 不能发布。总 SSE 数据上限 8 MiB，最终结果仍受 2 MiB 限制。共用结构工具只增加可选 chapters 根字段、store 和响应字节限制，既有调用默认不变。

学习批次记录实际采用的模型、传输和独立预算，并保存 Provider 报告的 tokens 与安全状态/时长；没有返回 usage 就保持缺失，不估算为零。不保存原始错误正文、推理、密钥或 endpoint。结构与来源通过仍不等于语义正确；`store:false` 也不替代 Provider 数据保留条款。

当前硬性资源保护是输入最多 120,000 字符、结果最多 2 MiB、章节最多 200、每章最多 1,000 个节点；这些是验证器的资源上界，不是学习点目标或 Work 的 20 项规则。超出就明确失败，不截断、不循环凑内容。较长材料需先缩小范围，待真实样本触及上下文或输出上限后再决定自然分块方案；本轮不预建通用长任务系统。

## 录音保存、公司 ASR 与恢复（2026-09-21）

- 正常上传已有录音，可和文本/PDF 同批保存；不做现场录音或回听。单份暂限 64 MiB/2 小时，每批录音 128 MiB/2 份。原有 PDF 20 MiB/200 页、文本限制不变。这些是当前 multipart 多副本、SQLite BLOB 和有限本地处理预算的资源上限，不是已做最大负载验收；后续真实样本频繁触顶才评估流式上传，不能无依据直接放大。
- 复用 `validateAudioUpload`、`measureDailyReflectionAudio` 与 `planAudioChunks/splitAudioWithFfmpeg`，不进入通用上传。音频工具仅新增学习可选的本地协议白名单/取消/超时参数，既有产品默认路径不变。保存时本地时长/格式检查，不调用 ASR；运行时归一化选取第一条音轨，按 300 秒分片，mono 16 kHz MP3。转写位置为音轨起点起算的秒数。
- 用户勾选范围并手动“转写所选录音”后，学习服务仅发送选中录音分片。文本/PDF 不送 ASR，转写成功不会自动调用 DS。配置使用既有 `SPEAKER_ASR_BASE_URL`、`SPEAKER_ASR_AUDIO_BASE_URL`，新增独立 `LEARNING_ASR_AUDIO_CAPABILITY_SECRET`（至少 32 字符）。不启用其他 ASR、不建立模型/人物关联、不接受 provider fallback。
- 公司接口仍是 `/api/ai/non-realtime-asr` 和 `/query?reqid=...`。`requestCompanyAsr` 是现有传输的最小导出，返回原有结果对象；学习层独立检查正文和真实 timestamps，不使用通用 adapter 的缺失时间默认值，也不做人物身份匹配/分类。
- 账号 SQLite 内存储原音、不可变分片计划、请求 ID、完成分片、最终转写。处理副本在账号/学习页/材料专属目录，Windows 长路径显式 namespaced；正常处理 finally 清理，删除还清理上次异常退出残留。归一化分片只通过独立签名 GET/HEAD 取音，签名绑定账号/学习页/本批/材料/分片，5 分钟有效；每次校验活跃任务和本地归属。没有登录用户可回听的原音接口，Range 不支持且不能绕过鉴权。Next 开发日志仅排除该签名路由，避免日志记录临时 capability。
- 每页同时一批；材料与分片串行。完成分片不再提交，结果未知先持久化 request ID，手动恢复只查询该 ID，不自动 POST 重放。已有检查点恢复仍使用学习自己的 fencing 与存储，不能直接复用会写通用 JsonStore 的 checkpoint repository。原音在成功后保留，已完成分片的临时音频字节清除，正文检查点保留直到删除。暂不重新转写已完成原音。
- 一个材料失败，其余材料继续；整个材料完整转写后才成为框架来源。没有时间戳、超出分片范围、没有正文都不发布假转写。时间戳、段落、原音哈希绑定框架来源；转写正文变化也使在途框架绑定失效。ASR 成功不等于语义正确。
- 12 分钟无有效推进的批次失效，每个分片最多等待 10 分钟，归一化最多 120 秒。刷新/重登录显示实际分片进度；进程中断不自动重放，需手动恢复。若公司服务已遗忘未知请求、或提交前进程退出，当前会保留原音并失败；本阶段没有可安全证明“从未提交”的自动重提平台。
- 删除材料使任务失效，删除原音、转写正文、分片/来源缓存与临时处理目录；已保存框架和笔记保留，来源无法回看。删除学习页清除现有全部归属对象。迟到回调不可创建材料或发布成果。临时文件清理若失败明确返回错误，重复删除可继续清理。
