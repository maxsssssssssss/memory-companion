# Daily Brief Agent A2

A2 延续 A1 的 `structured_action_v1`、LangGraph 和 SQLite 路线，增加任务内目标/授权调整、确认笔记追加及分类恢复。Cloud 使用合成教材和明确标注的离线 Provider；应用认证、API、Quiz、评分、笔记、任务库和 checkpoint 实际执行。离线轨迹不是模型自主决策、生成质量或学习效果证据。Windows 完整真实业务验收仍为 PENDING；生产部署 NOT RUN。

## 基线与 JSON 兼容修复

从 A1 `c0786b48947cdc059052c6b07d421f290cc3f1d1` 创建 `feat/learning-agent-a2`。用户报告的 Windows 最小协议 PASS 仅属于这个 A1 SHA，不扩大到完整 Learning 或新提交。

独立提交 `0feb4721de0734dc2bb1dac8390cd4659293a553` 修复共享 JSON 提示冲突：省略 `jsonRootField` 仍要求 `items`；显式 `items/results/chapters` 保留原语义；`null` 明确表示不指定根字段。正式 Agent 决策和 `protocol-structured.ts` 都显式使用 `null`，仍经合法 JSON 与严格行动 schema 校验。没有套一层 items、忽略额外字段、原生 tool calling 探测或隐式协议回退。

## 用户流程

- 在原学习页的「自适应复习·试用」开始任务、打开原 Quiz 组件作答、读回实际成绩，再继续决策。任务内解释与原个人笔记分别保存。
- 「调整本轮复习」支持修改目标及当前页材料、章节、知识点和历史/笔记/补充权限。先显示前后范围，再明确确认；撤销立即约束后续读取和发布。并发版本冲突保留草稿，须比对新版本后再次确认。
- Agent 可以提出把当前版本解释追加到可靠知识点。用户看到准确目标、正文、来源、材料外补充标记，批准或拒绝；普通读取、Quiz 和任务内解释无额外审批。读取笔记权限不是写笔记权限。
- 暂停、继续、取消、调整、核对原操作、明确失败项重试和结束交回依据实际状态提供。unknown 不显示通用重试。等待作答或确认时刷新不调用模型。
- 笔记成功追加后本轮交回并结束；继续复习需新建任务。这个有意限制避免本次写入改变冻结笔记观察后仍沿用旧授权证据；不宣称已通过检查。
- 争议题组继续沿用原「题目有疑问」路径，停止用该组评分判断薄弱点，不改旧答案或成绩。结束不等于掌握，不生成长期掌握率。

## 共享机制与业务边界

共享层 `src/lib/server/agent/` 负责版本 CAS、行动身份、调用预算、租约、确认绑定、恢复和日志；不导入 Learning repository、Quiz 类型或评分。正式包保持 `@langchain/langgraph@1.5.0`、`@langchain/langgraph-checkpoint-sqlite@1.1.0`、`@langchain/core@1.2.17`（MIT），没有新增生产依赖或第二运行时。上游版本、源码与复用依据见 A1 文档，本轮不重复选型。

LangGraph 的 `StateGraph`、`interrupt`、`Command` 和正式 SQLite Saver 继续管理执行位置。版本 1 保留旧 thread ID；后续版本使用独立版本 thread ID。prepare 节点让已保存提案的恢复复用原行动，不能因 SDK 重放再选一次或重复副作用。checkpoint 只存 ID/路由，不保存材料、完整工具观察或笔记正文。

`agent-tasks.sqlite` 仍是任务生命周期、授权、预算和行动收据权威；增量增加版本、恢复状态和两个小表 `agent_approvals`、`agent_controls`。审批绑定账号、任务版本、工具、参数、目标、正文及来源指纹，共享库不保存审批正文。事件按任务版本和业务身份去重，控制事件记录语义指纹；重复同一批准只读回，换事件 ID 改决定也不能复用原批准。

Learning 的 `agent-scenario.ts`、`agent-notes.ts`、`agent-repository.ts` 负责授权材料语义、解释、Quiz 结果、笔记预览和结束说明。原 `learning_agent_artifacts` 增加 `task_version` 和笔记提案种类。新增笔记调用现有框架编辑服务的追加方法，用 revision/hash 检查目标变化；笔记追加与业务收据同一 SQLite 事务。原题组、作答与评分服务继续是业务权威。

调整后旧行动正文参数和旧反馈内容不继续作为模型上下文；旧版本业务对象仍保留。API 不投影旧解释或可用题组引用；当前来源失效时隐藏正文/预览。材料删除清除对应提案正文，来源重解析或授权撤销不能经 checkpoint 绕过。成功终态不会因为之后来源变化重新变成待处理任务。

## 恢复与预算

恢复先查询原业务 operation 与收据，成功创建直接复用。提案尚未执行时恢复原确认等待；明确失败仅在现有业务重试契约允许时重试原操作。Quiz 保留原分段生成上限和 unknown 禁重放约束。无法查询的 Provider unknown 保持需要处理，不虚构查询能力。

运行中异常退出不自动重播所有 running。重启后可明确暂停废止旧租约，再核对原结果；inspect 不启动模型。核对得到 ready 时由用户继续。暂停/取消/调整使迟到响应不能发布或推进旧版本；已发生调用仍记账，已完成业务写入按原契约保留。不是全系统 exactly-once。

决策和工具内部生成都通过同一调用账本；修改目标、暂停、恢复不重置 calls、steps 或 compute。等待不占计算时间。崩溃后无法获得精确结束时刻的租约耗时保守结算并标记估算；usage 缺失为未知，不算零、不报精确费用。SDK/传输无隐式自动重试，trace/遥测保持关闭。

## 接口与兼容

没有新增顶层产品入口或全站审批 API。现有 `/api/learning/pages/[pageId]/agent` 的 PATCH 增加 `adjust`、`approval`、`recover` 和 `end`；都沿用账号认证、页面资源、事件 ID 和服务器权限检查。A2 mutation 携带 `expectedVersion`；旧正常控制只有版本 1 可省略，后续版本必须明确匹配。

打开 repository 时自动幂等增量迁移。A1 行默认为版本 1，保留原业务对象与 checkpoint；固定 A1 fixture 验证等待、已认证待消费事件恢复一次及重复请求零调用。无法安全恢复的执行点交回用户，不能静默从头跑。数据不能直接降级由 A1 写入；回退使用独立 checkout 和迁移前副本。
